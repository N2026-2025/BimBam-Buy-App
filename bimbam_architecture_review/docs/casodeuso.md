
### 📋 Caso de Uso: CU-01 - Procesar Consulta de Soporte


| Atributo              | Detalle del Flujo de Negocio                                                                                                                                                                                                                                                                                                                                                                                               |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Nombre**            | Procesar Consulta de Soporte con Evaluacion de Reembolso Automatizado.                                                                                                                                                                                                                                                                                                                                                     |
| **Actor Principal**   | Cliente Autenticado mediante JWT.                                                                                                                                                                                                                                                                                                                                                                                          |
| **Precondiciones**    | El cliente posee una sesion activa. El sistema tiene acceso a ChromaDB y RabbitMQ.                                                                                                                                                                                                                                                                                                                                         |
| **Flujo Basico**      | **1.** El cliente envia consulta con `id_cliente` e `id_orden_ref`. **2.** El Gateway inyecta el `X-Correlation-ID` en los headers. **3.** El Repositorio busca politicas en ChromaDB usando `ONNXEmbedder`. **4.** El LLM determina que cumple las reglas (`aplica_reembolso == true`). **5.** Se publica el evento JSON de forma asincronica en RabbitMQ. **6.** Se retorna un DTO con el estado `PROCESANDO_REEMBOLSO`. |
| **Flujo Alternativo** | **4a. No califica:** Si la IA determina que no aplica el reembolso, la entidad se guarda como `RESOLVIBLE_POR_CHAT` y se responde con texto del LLM, omitiendo el broker.                                                                                                                                                                                                                                                  |
| **Flujo Excepcion**   | **3b. Timeout en Servicios:** Si ChromaDB o el LLM fallan tras los reintentos, el controlador captura el error y devuelve un mensaje de contingencia junto al Correlation ID.                                                                                                                                                                                                                                              |



| Campo de la Especificación | Detalle Técnico y Reglas de Negocio Distribuidas |
| :--- | :--- |
| **Caso de Uso ID** | **CU-01** |
| **Nombre del Caso de Uso** | Procesar Consulta de Soporte con Evaluación de Reembolso Automatizado. |
| **Alcance** | Ecosistema de Microservicios BimBam Buy (`ai-support-service`). |
| **Nivel** | Nivel de Objetivo de Usuario (User Goal Level). |
| **Actor Principal** | Cliente Autenticado. |
| **Disparador (Trigger)** | El Cliente envía una pregunta o reclamo de reembolso a través del componente gráfico del chat. |
| **Precondiciones** | 1. El cliente debe poseer una sesión activa iniciada con un token JWT firmado y válido.<br>2. El microservicio de soporte IA debe tener conectividad operativa con la base vectorial ChromaDB y las credenciales del gateway LLM configuradas. |
| **Postcondiciones de Éxito** | El mensaje del cliente es respondido, los PDFs de políticas fueron consultados, el evento asincrónico `ReembolsoSolicitadoPorIA` es inyectado de forma persistente en RabbitMQ con su respectivo Correlation-ID, y la sesión se almacena con estado `PROCESANDO_REEMBOLSO`. |
| **Postcondiciones de Falla** | Ante un error técnico severo de infraestructura, el sistema captura la excepción, corta la falla en cascada, responde al cliente con un mensaje de contingencia amigable y persiste los logs indexados con el Correlation-ID para auditoría. |
| **Flujo Principal (Escenario Feliz)** | **1.** El Cliente introduce su consulta en la UI, enviando los parámetros `id_cliente`, `id_orden_ref` y el string `prompt`.<br>**2.** El `API Gateway` intercepta la llamada por HTTP, valida la firma del JWT, genera un UUID único (`X-Correlation-ID`) y delega la ejecución al método `post_ask()` del componente `SupportController`.<br>**3.** El `SupportController` extrae los datos del DTO de entrada y los pasa limpios al método `evaluate_client_policy()` expuesto por el objeto de negocio `SupportRepository`.<br>**4.** El `SupportRepository` ordena al `ChromaDAOImpl` buscar similitudes semánticas. Este usa un subcomponente local `ONNXEmbedder` para convertir el texto en un array de floats y ejecuta la consulta de vectores retornando una lista de strings con las cláusulas de los PDFs de políticas.<br>**5.** El `SupportRepository` acopla las cláusulas, estructura el prompt final y lo despacha al endpoint resiliente a fallas administrado por `LLMClientGateway`.<br>**6.** La API del LLM retorna la deducción semántica. La lógica de negocio analiza el objeto devuelto y comprueba que la regla se cumple con éxito: `aplica_reembolso == true`.<br>**7.** El `SupportRepository` invoca al componente de infraestructura `RabbitMQPublisherDAOImpl` mediante su método `insert_refund_event()`, el cual introduce un payload JSON plano estructurado en la cola de mensajería `orders.reembolsos` en modo persistente (`delivery_mode: 2`) acoplando la traza del `Correlation-ID`.<br>**8.** El repositorio instancia la entidad de dominio `SupportSessionEntity` guardando la sesión en memoria técnica bajo el estado `PROCESANDO_REEMBOLSO`.<br>**9.** El controlador devuelve al cliente un objeto de transferencia de datos `AskResponseDTO` que contiene el texto de la IA, el ID de correlación y la bandera de éxito de procesamiento. |
| **Extensiones (Flujos Alternativos)** | **6a. La IA determina que la solicitud del usuario no califica para reembolso (`aplica_reembolso == false`):**<br>&nbsp;&nbsp;&nbsp;&nbsp;1. El `SupportRepository` lee el veredicto del modelo de lenguaje y descarta que se cumplan las directivas de las políticas.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. El sistema omite por completo la llamada al `RabbitMQPublisherDAOImpl`, evitando encolar mensajes innecesarios.<br>&nbsp;&nbsp;&nbsp;&nbsp;3. El repositorio inicializa el estado de la entidad como `RESOLVIBLE_POR_CHAT`.<br>&nbsp;&nbsp;&nbsp;&nbsp;4. El flujo reengancha en el paso 9, entregando la respuesta conversacional común y el ID de traza al Cliente de forma ordinaria. |
| **Subvariaciones de Excepción** | **4b/5b. Falla de conexión o agotamiento de tiempo de respuesta (Timeout) en ChromaDB o Gateway LLM:**<br>&nbsp;&nbsp;&nbsp;&nbsp;1. El DAO vectorial o el cliente HTTP disparan un error interno tras superar la política de reintentos configurada.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. La excepción es capturada por el bloque de control del `SupportController` mediante un mecanismo de cortocircuito (*Circuit Breaker*).<br>&nbsp;&nbsp;&nbsp;&nbsp;3. El controlador aborta la operación distribuida y formatea un `AskResponseDTO` alternativo indicando un error temporal.<br>&nbsp;&nbsp;&nbsp;&nbsp;4. El sistema escribe un log de error crítico en consola emparejado con el `Correlation-ID` inyectado originalmente y el flujo finaliza en estado de falla controlada de forma segura. |
